02 · External Connections
เว็บนี้เชื่อมต่อออกไปที่ไหนบ้าง
คลิกที่การ์ดแต่ละใบเพื่อดูรายละเอียดปลายทาง วิธีเชื่อมต่อ และตัวอย่าง endpoint

ฐานข้อมูลกลางเก็บทุกอย่าง: รายชื่อสมาชิก, คะแนน/เช็คชื่อ, ตั้งค่าบอส, คำขอ CP, คำขออุทธรณ์, บัญชี Admin, ของรางวัล, log การแก้ไข ฯลฯ ทุกจอ sync กันทันทีผ่าน listener (onValue) โดยไม่ต้องรีเฟรชหน้า

reddevil-f229e-default-rtdb.asia-southeast1.firebasedatabase.app

ใช้ในแทบทุก workflow ของแอป เพราะเป็น "แหล่งความจริง" เดียวที่ทุกโมดูลอ่าน/เขียนร่วมกัน

ซิงค์ข้อมูลคะแนน/การล็อกสัปดาห์ไปสำรองไว้ใน Google Sheets เป็น backup ภายนอก ใช้ตอน push คะแนนใหม่, ปิดรอบสัปดาห์, หรือรีเซ็ตรอบ

script.google.com/macros/s/AKfycb.../exec

เรียกจากฟังก์ชัน pushToGoogleSheets(), closeGoogleSheetsCycle() เป็นต้น — เป็น one-way ส่วนใหญ่ (client → sheet)

หน้าเว็บ ไม่ได้ยิงหา Discord API โดยตรง — มันเขียนคำสั่งลงโหนด bot_commands/* ใน Firebase แล้วมี Node.js bot ตัวแยก (bot.js) คอยฟังและส่งประกาศ/ซิงค์สมาชิก Discord กลับเข้ามาที่ node discord_server_members

guild_app/bot_commands/send_announcement

รูปแบบนี้เรียกว่า "command queue pattern" — client เขียนคำสั่ง ส่วน bot อีกตัวคอยเฝ้าดูและทำงานจริงฝั่ง Discord

วิเคราะห์รูปภาพด้วย AI: อ่านสกอร์บอส/ของดรอปจากภาพหน้าจอ, ตรวจรายชื่อคนเข้าร่วมชุมนุมจากภาพ, และเป็นสมองของแชทผู้ช่วย "น้องเดวิล"

generativelanguage.googleapis.com/v1beta/models/...

API Key เก็บใน localStorage ของเบราว์เซอร์ Admin เอง ไม่ได้ฝังในโค้ดกลาง

เครื่องมือ OCR สำรองที่รันในเครื่อง ใช้เมื่อยังไม่ตั้งค่า Gemini API Key — อ่านตัวเลข/ชื่อจากภาพสกรีนช็อตแบบไม่ต้องพึ่ง API ภายนอก แม่นยำน้อยกว่า Gemini แต่ใช้งานได้ฟรีทันที

cdn.jsdelivr.net/npm/tesseract.js@5

โหลดไลบรารีจาก CDN: Tailwind CSS, Font Awesome, Google Fonts, html2canvas (ใช้ export สรุป Top 10 เป็นรูปภาพ), Firebase SDK — เป็นไฟล์ประกอบหน้าเว็บ ไม่มีข้อมูลผู้ใช้ส่งออกไป

03 · Workflows
ขั้นตอนการทำงานของแต่ละโมดูลหลัก
คลิกหัวข้อแต่ละอันเพื่อขยาย/ย่อดูลำดับขั้นตอนแบบละเอียด
  • ผู้ใช้เปิดเว็บ → ระบบตรวจ localStorage ว่าเคยล็อกอิน Admin ค้างไว้หรือไม่
  • ถ้าเป็น Admin: กรอกอีเมล+รหัสผ่าน → เทียบกับ node admin_accounts ใน Firebase (ไม่ใช้ Firebase Authentication แต่ตรวจรหัสผ่านเอง) → Firebase
  • ระบบตรวจ role: Super Admin / Admin / Boss Admin เพื่อกำหนดสิทธิ์และเมนูที่มองเห็น
  • ผู้ที่ยังไม่ใช่ Admin กด "ขอสมัครเป็น Admin" → บันทึกคำขอที่ pending_admins ให้ Super Admin อนุมัติ
  • สมาชิกทั่วไปยืนยันตัวตนด้วย PIN 4 หลัก ต่อตัวละคร (เก็บที่ member_pins) สำหรับทำรายการที่ต้องยืนยันตัวตน
  • Admin เปิดตารางกิจกรรมประจำสัปดาห์ → ติ๊กชื่อสมาชิกที่เข้าร่วมแต่ละกิจกรรม (รายคนหรือติ๊กทั้งกิลด์พร้อมกัน)
  • ทุกการติ๊ก เขียนสดเข้า Firebase ทันที ที่ members_data / weekly_history → Firebase → หน้าจอทุกคนอัปเดตพร้อมกันแบบเรียลไทม์
  • คะแนนรวมและแดชบอร์ดสรุปด้านบนคำนวณใหม่อัตโนมัติจากข้อมูลที่เปลี่ยน
  • ทุกการแก้ไขถูกบันทึกลง audit_logs เพื่อดูย้อนหลังได้ว่าใครแก้อะไรเมื่อไหร่
  • เมื่อจบสัปดาห์ Admin กด "ปิดรอบสัปดาห์" → ล็อกข้อมูล (locked_weeks) และซิงค์สรุปไป Google Sheets → Google Sheets
  • ระบบแสดงนาฬิกานับถอยหลังของบอสแต่ละตัว โดยคำนวณจากเวลาตายล่าสุดที่บันทึกไว้ใน activities_data
  • เมื่อบอสตาย Admin แนบ สกรีนช็อตของดรอป → ระบบส่งภาพไปให้ AI วิเคราะห์: ถ้ามี Gemini API Key จะยิงไปที่ Gemini Vision → Gemini API, ถ้าไม่มีจะใช้ Tesseract.js แทน → Tesseract.js
  • AI อ่านชื่อไอเทม/ผู้รับของออกมาเป็นข้อมูล → ขึ้นหน้าต่างให้ Admin ตรวจทานก่อนกดยืนยัน
  • เมื่อยืนยันแล้ว บันทึกเวลาตายและของดรอปกลับเข้า Firebase → ตั้งเวลานับถอยหลังรอบใหม่โดยอัตโนมัติ
  • ฟีเจอร์เดียวกันนี้ใช้สแกนภาพ "รายชื่อคนเข้าร่วมชุมนุม" เพื่อติ๊กชื่อกิจกรรมแบบอัตโนมัติ
  • สมาชิกยื่นคำขอ 3 ประเภทได้เอง: ขอปรับค่า CP (pending_cp), อุทธรณ์การเช็คชื่อ (attendance_appeals), ขอแก้ข้อมูลตัวละคร (char_edit_requests)
  • คำขอทั้งหมดถูกเขียนลง node "pending" ของ Firebase ก่อน ยังไม่มีผลกับข้อมูลจริง → Firebase
  • Admin เห็นแจ้งเตือนคำขอค้าง → เปิดหน้าต่างพิจารณา อนุมัติหรือปฏิเสธพร้อมระบุเหตุผล
  • เมื่ออนุมัติ ระบบย้ายข้อมูลจาก node pending เข้าไปอัปเดต members_data จริง แล้วลบออกจากคิว
  • ทุกการตัดสินใจถูกบันทึกใน audit_logs เพื่อความโปร่งใส
  • Admin เพิ่มของรางวัลเข้าคลัง (reward_store_items) พร้อมจำนวนคะแนนที่ต้องใช้แลก
  • สมาชิกดูแคตตาล็อก → กดแลกของรางวัล → ระบบตรวจคะแนนคงเหลือก่อนสร้างคำขอแลก
  • คำขอแลกเข้าคิวให้ Admin อนุมัติและจัดการส่งมอบจริง บันทึกไว้ที่ reward_store_logs
  • เมื่ออนุมัติ ระบบตัดคะแนนของสมาชิกคนนั้นออกจากยอดสะสมใน Firebase
  • แชทลอยมุมจอ ผู้ใช้พิมพ์คำถามหรือแนบรูป → ส่ง prompt พร้อมข้อมูลกิลด์ไปให้ Gemini → Gemini API
  • มีปุ่มคำถามลัด เช่น "ของดรอปล่าสุด", "บอสใกล้เกิด", "สรุปยอดปันผล", "เช็คคนขาดกิจกรรม"
  • เมื่อ AI ร่างประกาศกิลด์วอร์เสร็จ Admin กดปุ่ม "ส่งเข้า Discord" → ระบบเขียนคำสั่งลง bot_commands/send_announcement ใน Firebase
  • Discord Bot ที่ฟังอยู่ตลอดเวลาจะหยิบคำสั่งนี้ไปโพสต์ลงห้องประกาศ Discord จริง → Discord Bot
  • ไอเดีย/ปัญหาที่คุยกับ AI สามารถบันทึกลง "สมุดบันทึกแอดมิน" (nong_devil_feedback_logs) เพื่อดูย้อนหลัง
  • ทุก 3 นาที (และเมื่อสลับกลับมาที่แท็บ) เบราว์เซอร์จะ fetch ไฟล์ version.json จากโฮสต์เดียวกัน
  • เทียบค่า buildTime กับเวอร์ชันที่โหลดไว้ตอนแรก
  • ถ้าพบว่ามีเวอร์ชันใหม่กว่า → ขึ้นแบนเนอร์แจ้งเตือนพร้อมนับถอยหลัง 5 วินาที แล้วรีโหลดหน้าอัตโนมัติ เพื่อให้ทุกคนใช้โค้ดเวอร์ชันล่าสุดตรงกัน

05 · Notes
คำถามที่พบบ่อย
ไม่มี — เป็นไฟล์ HTML/JS ไฟล์เดียวที่รันบนเบราว์เซอร์ผู้ใช้ทั้งหมด (Client-side only) โดยใช้ Firebase Realtime Database เป็นฐานข้อมูลกลางแทนเซิร์ฟเวอร์ของตัวเอง
เพราะ Discord Bot token ต้องเก็บเป็นความลับฝั่งเซิร์ฟเวอร์ ไม่ควรฝังไว้ในโค้ดฝั่ง client ที่ทุกคนเห็นได้ จึงใช้ Firebase เป็นตัวกลางส่งคำสั่งให้บอทแยกต่างหาก (bot.js) ทำงานแทน
ความปลอดภัยขึ้นอยู่กับ Firebase Security Rules ที่ตั้งค่าไว้ในโปรเจกต์ ต้องตรวจสอบให้แน่ใจว่ากำหนดสิทธิ์อ่าน/เขียนของแต่ละ node อย่างเหมาะสม เพราะ client เชื่อมตรงกับฐานข้อมูลโดยไม่มี backend คั่นกลางตรวจสอบสิทธิ์อีกชั้น
ระบบจะสลับไปใช้ Tesseract.js เป็น OCR สำรองโดยอัตโนมัติ (แม่นยำน้อยกว่าแต่ยังใช้งานได้) ส่วนฟีเจอร์แชท AI "น้องเดวิล" จะใช้งานไม่ได้จนกว่าจะตั้งค่า API Key ใหม่
💡 สรุปสั้น ๆ: Firebase Realtime Database ทำหน้าที่เป็นทั้งฐานข้อมูลและ "ตัวกลางส่งข้อความ" ระหว่างหน้าเว็บกับ Discord Bot ส่วน Google Sheets ใช้เป็นที่สำรองข้อมูล และ Gemini/Tesseract ใช้เฉพาะตอนต้องอ่านข้อมูลจากรูปภาพเท่านั้น
